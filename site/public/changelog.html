Changelog

What changed in each StockFW version, up to the current 1.0.7 release.

Each release also adds a chapter to the architecture and security document, which records the evidence behind every claim below. This page is the short version.

1.0.7 · 3 November 2026 · current release#

Added#

  • The What-If engine. A parser that reads a question the way you say it and shows how it read it; an engine that models your platform’s firewall (first match on Linux, block wins on Windows) together with the Firewall preferences, Sentinel’s blocks, whether the firewall runs and whether the saved policy is live; DEPENDS answers that spell out the split; the whole trace of rules checked; and fixes verified against the policy before they are offered. A window beside the page, not over it, and the same answer from stockfw simulate, with exit 6 for DEPENDS. Verified test-whatif.c Verified ui-simviz-smoke
  • Preferences redesigned. A grouped sidebar, a title and purpose line on every page, settings in titled groups, change marks before you save, and firewall settings applied under the last applied policy. Preferences. Verified ui-prefs-smoke
  • Background mode and the tray. StockFW --background starts in the notification area; the tray menu shows the firewall state and today’s blocks, the last five blocks, every page, Pause protection, Pause Sentinel, Start at sign-in and Help. If no notification area takes the icon, the window is shown instead. Background, tray and sign-in. Verified fs-traymenu-smoke
  • One StockFW per user. Starting it again brings the running copy forward; StockFW --quit asks it to quit cleanly; a launch with more rights takes over from the copy without them. Verified test-instance.sh
  • Start at sign-in. A Task Scheduler task that runs without administrator rights on Windows, an autostart entry on Linux; set from the tray, Preferences › General or --enable-autostart. Verified test-autostart.sh
  • Boot service on Linux. The installer installs and enables stockfw.service, which puts the last applied policy back before the network comes up. Verified test-boot-start.sh
  • Saving while running. Settings and the Copilot’s baseline are written every five minutes when they changed, and when the session ends. Verified fs-session-smoke
  • Help and About. A Help window with a searchable sidebar, Back and Forward and links between topics, opened with F1 at the topic for the page shown, working offline. An About window with the credits, a licence summary that matches the source, both licence texts and Copy system info. Help and About. Verified fs-help-smoke
  • The Copilot, reworked. Fixed checks, no model, no network: port scans, repeated login attempts, timed contacts, fan-out, blocklist hits and baseline changes, each with a severity, an evidence drawer and actions; a block is offered only when What-If confirms it. A policy health check that reports duplicate, shadowed, unreachable and no-effect rules, broad allows, risky services open to the Internet and denies that reach no family, with fixes What-If has verified; “Changes made by the Copilot” with Undo; stockfw copilot health. Copilot. Verified test-health.c
  • Events at volume. The list holds 100,000 events by default and up to 1,000,000; a filter bar on direction, verdict, protocol, port or range, address or CIDR block and time; the filtered rows export to CSV; on Windows every event in a burst is read, up to 10,000 per poll. Events. Verified ui-hitview-smoke
  • Event history. Off by default; on, events are saved to daily files only your account can read, kept 30 days or 200 MB, read back at start on a worker thread, and searched by stockfw events --history. Verified test-eventstore.sh
  • Threat-intel blocklists on Linux and Windows. Opt-in public lists (Spamhaus DROP, abuse.ch Feodo Tracker, DShield, FireHOL, blocklist.de, Emerging Threats, CINS Army, Tor exits) and your own; each feed off until you accept its terms; strict parsing; protected ranges never blocked; one nftables table on Linux, a Windows Firewall rule group on Windows; a Threat Intel page, stockfw intel, a dashboard card, and Linux events that name the list. Threat intel. Verified test-feed.c Verified test-intelset.sh
  • Country and network blocking on Linux from IPFire’s signed location database (CC BY-SA 4.0), with an anycast warning, stockfw intel geo and a lookup that says “registered in”. Not on Windows in this version. Country and network blocking. Verified test-geodb.sh
  • IPv6 on Linux. One apply loads the policy into iptables and ip6tables, each in one atomic step; a refused IPv6 half rolls the IPv4 half back. Each rule shows which families it covers, and the Overview says whether IPv6 is filtered. Verified test-apply-dual.sh
  • The new look. A dark sidebar replaces the tab band, a new Overview answers “is this computer protected?”, every page is rebuilt as cards, and there is a new logo. The Windows Overview shows the firewall profile and the network in force.
  • Continuous integration. Linux and Windows builds and test suites on every pull request, with the Windows installer and the Linux tarball kept as artifacts.

Changed#

  • Linux events are read from the kernel ring buffer (/dev/kmsg), allowed new connections are logged too, and an empty Events list says why.
  • Windows rules use real protocols, port specs and sides; a rule is refused rather than widened.
  • Router mode on Linux uses its own NAT chains, replaced on every apply.
  • As root, StockFW runs iptables, ip6tables, nft and journalctl only from the system directories; on Windows it runs netsh, wevtutil and auditpol only from System32. Verified test-core.sh
  • stockfw dashboard hands the browser a private launch page, so the token is on no command line.
  • The Linux tarball’s binaries are stripped; the installer checks for liblzma.so.5 and libcrypto.so.3 and warns when nft or curl is missing. The Windows installer ships the README, this changelog and the licence file.

Fixed#

  • Generator bugs on Linux: outbound host rules that were never added, hyphenated port ranges, router-mode denies that were bypassed, forwards dropped after DNAT.
  • The Windows broadcast-block settings no longer create rules that block nothing; the switches are offered on Linux only.
  • The Copilot no longer offers Ask What-If or a block for traffic a list or a country rule already blocks.
  • Help says what StockFW downloads: the location database as well as the blocklists, each only after you accept, plus DNS lookups of host names in Linux rules.
  • Event history keeps events that arrive while it is being read back, and applies limits saved meanwhile.
  • Credits: the port is credited to the Stock Team in About and Help; the Windows file properties, the installer and both licence files carry one copyright line.

1.0.6 · development version, shipped as part of 1.0.7#

  • Activity page with two graphs over 15 minutes to 24 hours: events per minute (allowed and blocked) and adapter throughput, a crosshair, a table view, and a shaded “no data” band for time before the app started. Series are kept in 10-second slots for 24 hours at a fixed memory cost. Verified fs-activity-smoke
  • The stockfw command line on Linux: status, policy list|add|remove, apply [--dry-run], start, stop, simulate, events [-n N] [-f] [--blocked], connections, interfaces [--watch], dashboard; --json everywhere; exit codes 0, 1, 2, 3 and 5. Verified test-cli.sh
  • The local dashboard: a read-only page served from the binary on 127.0.0.1 only, behind a per-run token carried in the URL fragment and a custom header, with a Host check against DNS rebinding, GET and HEAD only, request-size and connection caps, and a per-run CSP nonce. Never opens a browser as root.
  • Linux events made truthful: the right fields in the right columns, the [BLOCKED] marker every consumer keys on, the kernel’s own time stamp, lines split across reads carried over.
  • Real network and connection panels on Linux from /proc/net/dev, sysfs and /proc/net/tcp, with the owning program found through /proc/<pid>/fd, and direction decided by the LISTEN table rather than guessed from port numbers.
  • Desktop fixes: literal mnemonics on buttons, a Windows path suggested on Linux, frame titles striking through their borders, a blank Events list that now says whether it is waiting, off or filtered to nothing, and a window that opened too small.
  • The Linux installer ships and installs the command line.

1.0.5 · 11 October 2026 · the hardening release#

  • Sentinel “no false outages”. After a 2026-10-10 incident in which auto-block locked the machine out of legitimate sites, six fixes: destination gates (never your own network, multicast, loopback, link-local or a destination the program already used regularly), a session cooldown so an expired block is not re-staged a second later, persisted staging reconciled at start-up with the remaining time honoured, the user’s Allow lifting Sentinel’s block, a text-format netsh parser with verified clearing (the old one deleted nothing and stacked 479 rules), and detect mode lifting every staged block. Verified test_sentinel_auto_gates
  • Application trust engine (the Trust page): streamed SHA-256, Authenticode verdict and signer on Windows, a baseline with five honest outcomes (new, unchanged, changed, gone, unreadable), attest and forget with audit lines, and a scan of running processes.
  • Explainable behaviour analysis: per-program baselines of ports, destinations, hours and rate, persisted across restarts; one finding per event listing every signal with its numbers; bounded tables that go quiet rather than cry wolf when full.
  • Safe policy enforcement: one apply gate for every path, an applied-policy journal, impact measured against what is live, a narrow delta path, audit-only testing mode, the Lock honoured at every apply site, verified rollback, and one audit line per attempt.
  • What-if simulator developed from a stub into the Copilot’s centrepiece, with verdicts that follow Windows Firewall precedence (block beats allow, shadowed allows reported), CIDR containment, and the Simulation Visualizer window. The conversational “AI Assistant” box was removed.
  • Bi-directional rules: a Direction setting on pairable rule kinds that stages the opposite-direction twin as one all-or-nothing save.
  • System tray with close-to-tray behind a gate that fails closed, and the two Preferences switches made real. Verified fs-tray-smoke Windows
  • Preferences made real on Windows: ICMP Filtering and Advanced Options compile to profile-scoped firewall rules through a portable settings plan; pages Windows cannot honour stay hidden rather than inert.
  • The P4 adversarial suite: 49 checks over seven named scenarios (blocked port scan, single-host sweep, C2 beacon, the incident replay, benign developer tools, exfil burst, rule rollback). Verified test-adversarial.sh
  • Linux first-run fixes: sudo’s search path explained instead of patched, a leaking iptables probe silenced, a profile box Linux could never honour hidden for good.

1.0.4 · October 2026#

  • Event → Rule in one click: right-click an event to block or allow its destination, block that service to it, or trust an inbound source, with the exact rule printed first and an honest “live” or “staged, needs administrator” result.
  • Events filter bar with “3 of 1200 events” counts.
  • Sentinel: beacon detection (metronomic egress to one host and port) and fan-out detection (60 distinct destinations, or 10 distinct blocked ones, in 60 seconds), with auto-block time-boxed to ten minutes and one-click undo, every action in an append-only audit.log.
  • Policy rows validated at load (hosts, ports, ranges, IPv6, CIDR) before netsh ever sees them; control characters stripped from rule names.
StockFW

A firewall manager for Windows and Linux. It drives the firewall your system already has, shows what it allowed and blocked, and works entirely offline.
