Install on Windows

StockFW ships as a single installer that includes everything it needs. Installing takes a minute; the only decision is where to put it.

Before you start#

  • Windows 10 or Windows 11, 64-bit.
  • Windows Defender Firewall must exist. It always does, even when another security product is installed; StockFW manages the Windows engine, not a third-party one.
  • An administrator account for installing, and for changing rules later. Reading events and editing the policy on disk do not need it.

Run the installer#

  1. Download and check it

    Get StockFW-1.0.5-Setup.exe and SHA256SUMS.txt from the download page. In PowerShell, Get-FileHash .\StockFW-1.0.5-Setup.exe must print the hash listed for it.

  2. Get past SmartScreen

    The installer is not code-signed yet, so Windows shows “Windows protected your PC”. Choose More info, then Run anyway. You checked the hash; that is what the signature would have told you.

  3. Accept the licence and choose a folder

    The default is C:\Program Files\StockFW. Keep it under Program Files if you can: that folder is writable only by administrators, which is part of what makes the elevated launcher safe to use.

  4. Choose components

    Main Application is required. Desktop Shortcut adds a shortcut to the ordinary, non-elevated app.

  5. Finish

    The installer can start StockFW for you. The first start is a good moment to open the elevated copy once, so monitoring gets switched on (below).

What gets installed#

WhereWhat
C:\Program Files\StockFW\StockFW.exeThe application. Its manifest says asInvoker: it runs with the rights of whoever starts it and never raises them itself.
…\StockFW\*.dll, lib\, share\, etc\The GTK 3 runtime, complete, so the app does not depend on anything else on the machine.
…\StockFW\StockFW-elevated.vbs, .cmd, .ps1The elevated launchers. Each finds StockFW.exe next to itself and asks Windows for administrator rights with a normal UAC prompt.
…\StockFW\README.md, CHANGELOG.mdThe project README and release notes.
Start menu › StockFWStockFW, StockFW (Elevated), Documentation, Uninstall.
Registry, HKLM\Software\StockFWThe install folder, and the usual entry under Apps & features.

Two ways to run it#

Normal: the “StockFW” shortcut#

Runs with your own rights. You can watch events (once monitoring is enabled), browse and edit the policy, run the simulator, inspect and attest programs, and change preferences. You cannot change the firewall: pressing Apply, Start or a profile switch fails with a clear message, “Administrator privileges required”, and the change stays saved for later. Nothing is half-applied.

Elevated: the “StockFW (Elevated)” shortcut#

Shows a UAC prompt, then runs with administrator rights. Apply, Start and Stop, the profile switches and Sentinel’s auto-block all work. Windows itself protects this window: a program running with ordinary rights cannot send it clicks or keystrokes.

How the launcher stays safe

The launcher resolves every path relative to its own folder, never from %TEMP%, your profile or the registry, and it refuses to start if the GTK runtime is not beside the executable instead of searching for one elsewhere. An earlier version added a build folder to PATH; that was removed, because a user-writable folder on an administrator’s search path is how a planted DLL gets loaded. Verified test-installer-spawn.sh

Enable monitoring#

Windows writes a firewall event for every connection only when the audit policy asks it to. On its first elevated run StockFW enables the Filtering Platform Connection subcategory with auditpol; running it again is harmless. After that, events 5156 (allowed) and 5157 (blocked) appear in the Security log and on the Events page.

If the Events page says monitoring is not enabled, open the elevated app once, or run this in an administrator PowerShell:

PowerShell
PS> auditpol /set /subcategory:"Filtering Platform Connection" /success:enable /failure:enable

This is the one machine setting StockFW changes that is not a firewall rule, and the app says so when it does it.

Where StockFW keeps its files#

Everything is yours to read, copy or delete. Nothing is hidden in a database.

FileHolds
%LOCALAPPDATA%\stockfw\inbound\…, outbound\…The policy, one file per rule kind. See Files and formats.
%LOCALAPPDATA%\stockfw\applied.csvThe last policy the firewall accepted: the journal Apply measures against and rolls back to.
%APPDATA%\stockfw\stockfw.confPreferences.
%APPDATA%\stockfw\audit.logOne line per apply, attest, forget and Sentinel action. Append-only.
%APPDATA%\stockfw\trust.csv, behavior.csv, autoblocksThe Trust baseline, the Copilot’s learned behaviour, and Sentinel’s staged blocks.

Rules StockFW creates in Windows Firewall are named StockFW-… (policy rules) and StockFW … (Preferences rules), so you can find them in wf.msc.

Update#

Run the new installer over the old one. Your policy, preferences and baselines are in your profile, not in the install folder, so they are kept.

Uninstall#

Settings › Apps, or Uninstall in the Start menu folder. The uninstaller removes the program, the runtime and the shortcuts. It does not remove the firewall rules StockFW created or your files in %APPDATA% and %LOCALAPPDATA%; press Stop firewall in the app before uninstalling if you want the rules gone, or delete the StockFW-… rules in wf.msc.

Build it yourself#

The newest code builds on Windows with MSYS2 in about five commands. See Build on Windows.
