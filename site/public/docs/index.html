StockFW documentation

StockFW is a desktop firewall manager for Windows and Linux. It does not filter packets itself. It configures the firewall engine your operating system already has, shows you every connection that engine allowed or blocked, keeps your policy as plain text, and lets you try a change before you make it.

Start here#

  • Install on Windows: the installer, the elevated shortcut, and enabling monitoring.
  • Install on Linux: the tarball, sudo and its search path, and the command line.
  • Your first ten minutes: check protection, watch events, add a rule, apply it, ask the simulator a question.

How StockFW is put together#

Four parts, and knowing them makes every page of the app predictable.

The engine
Your operating system’s firewall: the Windows Filtering Platform behind Windows Defender Firewall, or netfilter behind iptables on Linux. StockFW adds and removes rules in it through supported tools and never replaces it. If StockFW is closed or crashes, the engine keeps enforcing whatever was last applied.
The policy
What you want the engine to do, stored as one small comma-separated file per rule kind in your profile. The Policy page, the Copilot and the command line all edit the same files. Saving a rule does not change the firewall; Apply does.
The events
What the engine decided, read from the log it already writes: Security events 5156 and 5157 on Windows, the kernel ring buffer on Linux. StockFW never sees packets, only verdicts, and it shows them as they are.
The gate
Every path that could change the firewall, the Apply button, an event’s right-click menu, a Copilot suggestion, Sentinel’s auto-block, stockfw apply, goes through one function. It measures the change against what is live, records what it applied, rolls back if the engine refuses, and writes one audit line. There is no second door.

How to read these pages#

Claims about behaviour carry a stamp. A stamp is a promise about evidence, not decoration:

  • Verified test name An automated test in the repository proves it. The name is the test, so you can run it: most live in port/tests/ and in tests/test-core.sh.
  • Measured a number A number from an experiment that was run, such as the 150-second memory soak.
  • Known gap A limit StockFW has, written down so it is not mistaken for a feature.

Where the two platforms differ, a badge says which one a sentence is about: Windows Linux. Everything without a badge applies to both.
