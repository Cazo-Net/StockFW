Background, tray and sign-in

The firewall engine runs whether StockFW is open or not; StockFW in the background is what keeps watching events, learning, and, in auto mode, letting Sentinel act. The tray icon is how you know it is there and how you get it back.

Turning it on#

Two settings on Preferences › General, both on by default: Show a tray icon and Close and minimize to the tray. With both on, closing or minimising the window hides it and StockFW keeps running. With the icon off, closing the window quits the program; StockFW will not hide a window it cannot give back, because a background process with no way to reopen it would be a zombie with root rights. Verified ui-tray-smoke

Starting hidden#

StockFW --background (or --minimized) starts StockFW in the notification area with the window hidden. The Events page and everything behind it are built whether or not the window is shown, so a hidden copy lists and saves events exactly as a visible one does. If no notification area takes the icon, the window is shown instead, so nothing runs invisibly. Verified test-instance.sh

One copy per user#

Starting StockFW again does not start a second one: the launch hands over to the running copy and brings its window forward, then exits. StockFW --quit asks the running copy to quit cleanly, saving its settings on the way. A launch with more rights takes over from a copy with fewer: sudo StockFW replaces your unprivileged copy, and on Windows StockFW (Elevated) replaces the ordinary one, after the old copy has closed its files. Verified test-instance.sh

The icon and its tooltip#

The tooltip reads StockFW, Protected or StockFW, Not protected, with the engine’s name, from the same state the Overview shows; when the state cannot be read it says Firewall state is unknown rather than guessing. The icon follows the state too, so the answer to “is my firewall running?” is one glance.

The menu#

  • A status header: the firewall state and the last few blocks, live.
  • Open StockFW brings the window back.
  • Pause protection and Pause Sentinel, and Start firewall or Stop firewall, so the common actions never need the window. What the running copy cannot do, because it has no root or administrator rights, is greyed with the reason rather than offered and failed.
  • Start at sign-in, a switch; see below.
  • Preferences, Help (opens the Help window at the “Running in the background” topic, leaving the main window hidden) and About StockFW.
  • Quit StockFW ends the program. It does not stop the firewall: the engine keeps enforcing whatever was last applied, exactly as it would if StockFW crashed. To stop filtering, use Stop firewall here or in the window, or run sudo stockfw stop.

Start at sign-in#

From the tray menu, from Preferences › General, or with StockFW --enable-autostart and --disable-autostart. On Windows it is a Task Scheduler task that runs without administrator rights, so no UAC prompt appears at sign-in; on Linux it is an XDG autostart entry in ~/.config/autostart. Both start the unprivileged copy in the background: it monitors and learns, shows the firewall state as it can read it, and the elevated shortcut or sudo is still what changes the firewall. The uninstaller removes your entry. Verified test-autostart.sh

At boot, before anyone signs in#

Windows Windows Firewall rules persist, so StockFW’s rules are in force from boot. Linux iptables rules are gone at boot, so the Linux installer enables stockfw.service, which loads the last policy applied as root before the network comes up. The service and StockFW in the tray are separate things: one puts the rules back, the other watches them. At boot has the details. Verified test-boot-start.sh

What runs in the background#

  • Event monitoring, and everything fed by it: the Activity counters, the Copilot’s checks and what it learns, Sentinel’s detectors, and the event history if you keep one.
  • Sentinel’s ten-minute expiry timer for auto-blocks.
  • The hourly check for threat-intel feed updates, for the feeds you have turned on.
  • Saving: settings and what the Copilot has learned are written every five minutes when they changed, and when the session ends, so a crash loses at most five minutes.

Memory stays flat: the Activity series are fixed-size rings, the Events list is a fixed ring of the size you chose (about 7 MB at the default 100,000), the Copilot keeps the last 100 changes, and a 150-second soak at full event rate found no growth. Measured 150-second soak, docs chapter 9

Where the icon cannot appear#

A tray needs a tray host and an X11 display. GNOME has not shipped a host since 3.26; the AppIndicator extension restores it, and KDE, XFCE, MATE, Cinnamon and Windows have one built in. Without a host the icon simply does not show, the window keeps working (a hidden start shows it), and closing it quits, so nothing is lost. The project’s own tray test fails on a headless machine for this reason, and is expected to. Known gap

Linux GTK has a tray only on X11 and Windows. On a Wayland session (GNOME and KDE Plasma by default, and WSL’s WSLg) StockFW does not try to make one: a background start shows the window, closing the window quits, and Preferences greys both tray switches with the reason. The once-a-minute re-read of the firewall’s state, which is how stockfw stop in a terminal reaches the Overview and the sidebar, runs whenever the window is open, with or without a tray icon. Under sudo StockFW runs on XWayland, because sudo drops the Wayland display variables, so the tray works there as on X11. Verified test-notray.sh
