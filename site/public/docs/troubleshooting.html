Troubleshooting

StockFW tries to say what is wrong in the place where it is wrong. This page collects those messages, says what each one means, and what fixes it.

Privileges#

“Administrator privileges required”, “Not live yet: run `sudo stockfw apply’”, exit status 3
You are changing the firewall without the rights to do it. The change is saved and will be applied the next time Apply runs with rights. On Windows use the StockFW (Elevated) shortcut; on Linux run sudo /usr/local/bin/StockFW or sudo stockfw apply. Nothing was half-applied.
“sudo: StockFW: command not found”
Linux sudo does not search /usr/local/bin on Fedora, RHEL and some Kali systems (Ubuntu’s default includes it). Type the full path: sudo /usr/local/bin/StockFW. The installer warns about this and deliberately does not edit sudoers; see why.
“libcrypto.so.3 is OpenSSL 3” from install.sh
Linux The distribution ships only OpenSSL 1.1 (Debian 11, Ubuntu 20.04). StockFW links OpenSSL 3 and liblzma 5 to read the signed location database, and the installer stops before copying anything rather than install a program and a boot service that could not start. Upgrade the distribution, or build from source against the libraries it has.
“nft not found” or “curl not found” from install.sh
Linux A warning, not a failure. Without nft the threat-intel lists and country rules cannot be loaded, and without curl they cannot be downloaded; the Threat Intel page says so. sudo apt install nftables curl.
“Windows protected your PC” when running the installer
The installer is not code-signed yet. Check the SHA-256 against the download page, then More info, Run anyway.

Events#

“Monitoring is not available” on Windows
The audit policy that makes Windows write firewall events is off. Open the elevated app once; it enables it. Or run auditpol /set /subcategory:"Filtering Platform Connection" /success:enable /failure:enable in an administrator PowerShell. See Enable monitoring. If a domain policy forces auditing off, StockFW cannot override it and says so.
“Monitoring is not available” on Linux
The kernel log needs root. Start the app with sudo, or add yourself to the adm group for the command line’s events.
The list stays empty although the firewall is running
Read the sentence under the empty list. “Waiting for the first event” means nothing has been blocked or logged yet; try an inbound connection from another machine to a closed port. On Linux, allowed connections are logged only with Log allowed connections on; otherwise the page shows drops and rejects only.
No events in WSL2, a container or a network namespace
Linux The kernel delivers firewall log lines from a non-initial network namespace only when net.netfilter.nf_log_all_netns=1. Set it on the host: sudo sysctl -w net.netfilter.nf_log_all_netns=1. WSL2’s kernel also needs the netfilter log modules; a stock Ubuntu WSL image has them.
“(up to N skipped)” next to the event count
Windows More than 10,000 Security-log records arrived in one five-second poll. The newest 10,000 were read and the rest counted as an upper bound; the Security log keeps them all. On Linux the kernel log is read as it streams and nothing is skipped.
“Another copy of StockFW is saving the history”
Two copies of StockFW are running on the same account’s history folder, and only one may write it. The second lists events but saves nothing, and takes over by itself once the first is gone. StockFW --quit asks the running copy to quit.
The Program column is empty
Linux The kernel log carries no program name. The Overview’s connection table names programs for connections that are open; the Events page cannot for ones that are not. Known gap

Policy and Apply#

A rule I added is not applied
Linux Check which policy you edited. As yourself the policy is ~/.stockfw; as root it is /etc/stockfw. stockfw status prints the directory in use. Pick one identity for policy work; see Two homes.
“N malformed policy rules were skipped”
A line in a policy file did not parse: a non-numeric port, a host name starting with a hyphen, a stray comma. The line was skipped, not guessed at. Open the file named in the message, fix or delete the line, reload. Saving from the app writes only the rules that parsed. The format.
Apply says “policy held, firewall untouched”
Audit-only on the Policy page or Lock policy on the Overview is on. The change was measured and recorded; the engine was left alone. Turn the hold off and Apply again.
Apply failed and “the last good policy was restored”
The engine refused a rule. The dialog carries the tool’s own message; on Windows it is often a target netsh cannot parse, on Linux a rule the kernel lacks a module for. The policy on the wire is what it was before you pressed Apply. The audit log has the line.
“The forward to 192.168.1.30 was left out: no external interface is set”
Port forwards need router mode: set the Internet connected network device and Enable Internet connection sharing on the Network Settings preference page.
“NOT BLOCKED: name could not be looked up”
A deny rule’s target is a host name that did not resolve while the firewall was being started, so it was left out rather than refuse to start at all. Fix the name or use the address, then Apply again; while the firewall is running, the same failure refuses the apply and keeps the old addresses blocked instead.
A host-name rule covers nothing on Windows
Windows Windows Firewall takes addresses only. Use the address, or one rule per address. The Covers column warns.

IPv6#

The IPv6 tile reads “Not filtered: ip6tables is not installed”
Linux sudo apt install iptables brings ip6tables on Debian-family systems; dnf install iptables-nft on Fedora. Then Apply again. Until then only IPv4 is filtered, and the app says so rather than pretending. Known gap
“None on this system”
The kernel has no IPv6 stack. Nothing to filter, nothing wrong.

Copilot and Sentinel#

Sentinel blocked something I use
Press Undo on it under Changes made by the Copilot, or right-click the destination on the Events page and Allow destination: your Allow lifts the block and the two reach the firewall together. The block would have expired by itself in ten minutes; it cannot come back in this session. If it happens often, set Sentinel to Detect only, which takes every staged block down at once. Sentinel never blocks loopback, your LAN, multicast or a destination the program has used before; if it did, that is a bug worth reporting with the audit lines.
No findings appear
The page says why: no events yet, monitoring off (with the reason the Events page gives), or “No findings from N events”, which means none of the fixed checks matched, not that the computer is safe. Allowed traffic is seen only when allowed-event logging is on; without it the login check sees only refused attempts. A slow pattern can stay below every limit; the limits are on the Copilot page.
A health finding says “no fix offered”
The fix was tried against the policy with the What-If engine and one of its checks failed, for example a narrowing that would have cut off a second private network this computer is on. The failed check is printed under the finding. Nothing was changed.

Tray and window#

No tray icon
Your desktop has no tray host (GNOME without the AppIndicator extension, or a headless session). The window works as usual and closing it quits. See Background and the tray.
No tray icon on Wayland or in WSL, and both tray switches are greyed out
Linux GTK has a tray only on X11 and Windows. On a Wayland session (GNOME and KDE Plasma by default, and WSL’s WSLg) StockFW makes no icon: a background start shows the window, closing the window quits, and Preferences greys Show a tray icon and Close and minimize to the tray with the reason. Under sudo StockFW runs on XWayland instead, where the tray works as on X11. No Gtk-CRITICAL line is printed at start. Verified test-notray.sh
“This application can not open files” after StockFW dashboard or StockFW status
Linux That was the 1.0.7 message. The window app takes options only; a word such as dashboard belongs to the command-line tool. It now exits with status 2 and names the command you meant: sudo ./cli/stockfw dashboard from the unpacked folder, or sudo /usr/local/bin/stockfw dashboard once installed.
I closed the window and the app is still running
That is Minimize to the tray. Open it from the tray icon, start StockFW again (a second launch brings the running copy forward), or run StockFW --quit. Quitting does not stop the firewall.
StockFW does not start at sign-in
Turn it on in the tray menu or on Preferences › General, or run StockFW --enable-autostart. On Windows it is a Task Scheduler task without administrator rights; on Linux an entry in ~/.config/autostart. Both start the unprivileged copy in the background, which monitors and learns; changing the firewall still needs the elevated shortcut or sudo.

Command line and dashboard#

“cannot listen on 127.0.0.1:8080”
The port is taken. Leave out --port and the system picks a free one.
“Not live yet” in stockfw status, or stockfw apply after stockfw stop says nothing changed
Linux stockfw status says “N changes not applied”: run stockfw policy diff to see them and sudo stockfw apply to make them live. An apply after a stop now loads the whole policy and starts the firewall again; in 1.0.7 it compared the policy with the last apply, found no change and left the firewall stopped.
“the event reader stopped” from stockfw events -f
Linux The kernel log could no longer be read (the file named by STOCKFW_LOG_FILE was removed, or /dev/kmsg refused). The command says why and exits 1 rather than waiting forever; fix the source and start it again.
The dashboard did not open a browser, or the browser shows a file error
Under sudo StockFW will not start a browser as root. A snap or Flatpak browser cannot read the private launch file StockFW hands it. In both cases open the printed link in your browser, or run stockfw dashboard link for a fresh one.
“This link has expired” or “This link was already used”
A link works once, for two minutes. Run stockfw dashboard link for a new one. A link that was already used ends every open session and the terminal says so; if you did not open it twice yourself, someone else saw the link.
The dashboard page says the session ended, or shows “Unauthorized”
Sessions end after 12 hours, when the dashboard restarts, and when a link is used twice. Run stockfw dashboard link and open the new link in the same browser.
“the dashboard does not serve uid 0”
You started it as plain root. Run it as yourself, or with sudo from your own account: it then serves the account that ran sudo.
The browser shows nothing, or a page saying Windows browsers are not let in
Use http://127.0.0.1:port as printed, not localhost. Under WSL, a browser on the Windows side is refused unless the dashboard was started with --allow-windows; a browser inside WSL works as it is. See the dashboard page.

Uninstalling and starting over#

Rules are still in the firewall after uninstalling
By design the uninstaller leaves the engine as it is. Press Stop firewall before uninstalling, or afterwards: on Linux sudo iptables -D INPUT -j INBOUND; sudo iptables -F INBOUND; sudo iptables -X INBOUND and the same for OUTBOUND and the nat chains, plus sudo nft delete table inet stockfw_intel if lists were on; on Windows delete the StockFW- rules and the StockFW Threat Intel group in wf.msc.
Start from scratch
Stop the firewall, close the app, delete the two directories listed in Files and formats. The next start is a first run.

Reporting a problem#

Open an issue on GitHub with the system info (About StockFW › Copy system info copies the StockFW and GTK versions, the platform and the backend, and nothing about you or your computer’s name), what you did, what the app said, and the relevant lines of audit.log. Nothing in the audit log is secret, but read it before pasting; it names your rules’ targets.
