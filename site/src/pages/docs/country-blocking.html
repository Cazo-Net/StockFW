Country and network-owner blocking

Some servers have no business talking to any country but their own, and some attacks come from a handful of networks. 1.0.7 adds two more kinds of threat-intel set, built from an offline database rather than a feed: every address registered to a country, and every address announced by a network owner (an autonomous system).

Where this stands

This is round two of the 1.0.7 threat-intel work, after blocklists. The data source is decided and its reader is being written [[soon]]; the picker and the sets follow. The database’s licence terms are being confirmed with its publisher before release, and a fallback source is chosen in case they cannot be.

Where the data comes from

The IPFire Location database: one file, about 6 MB compressed, published daily, no account needed, with IPv4 and IPv6 in one structure. For every range it gives the country of registration, the announcing network (AS number and name), and flags for anonymous proxies, satellite providers and anycast networks. It is the same database the IPFire firewall uses for its own country blocking.

The file is signed inside its header with ECDSA over a SHA-256 of its contents, and StockFW verifies that signature against a pinned public key before reading a single record. A version check uses a DNS record the publisher maintains, and a downloaded file older than the one already on disk is refused, so a replayed old database cannot roll the data back. The reader unpacks with a strict size cap and bounds-checks every offset in the header before it trusts it.

If the licence cannot be confirmed in time, the fallback is DB-IP’s free country database with the iptoasn network-owner table, both unsigned, in which case StockFW relies on HTTPS, strict structure checks and keeping the last good copy.

What “country” means

The country is where the address block is registered, from the regional registries, geofeeds and the publisher’s corrections. It is not a measurement of where a packet came from, and for a content network that announces one address from forty cities it cannot be. StockFW therefore says “registered in”, never “located in”, and the picker warns when a chosen country’s ranges include anycast networks: blocking such a country can block a service everyone uses, from everywhere. The same honesty applies to network owners: the AS name is the owner on record.

How it will work

  • On the Threat Intel page, a picker with autocompletion over countries and network owners, each with its flag and the number of ranges it would add. A chosen entry becomes a set with a direction, like a feed.
  • The sets are built, subtracted, loaded and reported exactly like blocklists: the same protected ranges, the same exceptions, the same transaction into inet stockfw_intel, the same state table, the same events and audit lines. A country block that would include your own network, your DNS servers or your SSH peer loses those addresses and says so in the notes.
  • The lookup box, the What-if simulator and the Events page name the country or owner that blocked an address.
  • stockfw intel gains the country and owner commands, with --json.
  • The database updates on the same hourly check as the feeds, from the publisher only, after the same consent dialog.

What it is not

Not a geofence for a laptop that travels, and not a substitute for authentication: an attacker who wants to reach you from a blocked country rents a server in an allowed one. It removes background noise and narrows the field, which is worth having, and the app will describe it that way.
