Overview

The first page answers one question, “is this computer protected?”, in one sentence, and then shows the four things you would check next.

[[shot:overview|The Overview page: a green protection card with Stop firewall and View events buttons and four tiles reading IPv4 Filtered, IPv6 Filtered, Policy 10 rules and Engine Linux (iptables); counters for inbound and outbound events, open connections and traffic now; the open connections table, the network adapters card and the recent blocks list.|Protected, both families filtered, ten rules in force, one virtual adapter hidden and counted, and the last blocks with their source and time.]]

The protection card

Green with a shield when the firewall is running and your policy is in force; red when it is stopped. The sentence under the heading says what that means for traffic, and the four tiles break it down:

IPv4 traffic, IPv6 traffic
“Filtered” or “Not filtered”, separately. On Linux the IPv6 tile reads the real state of the kernel: if ip6tables is not installed, the IPv6 chains are not loaded, or they are loaded but not hooked, it says “Not filtered” and the sidebar shows the reason, rather than inferring IPv6 from IPv4. On Windows both read “Filtered” when the firewall is on, because Windows Firewall rules cover both families.
Policy
How many rules are saved. Saved is not the same as applied; the Policy page says which rules are live.
Engine
What is doing the filtering: Linux (iptables) or Windows Firewall. On Windows the card also shows the profile in force (Domain, Private or Public) and the network the computer is on, read through the firewall’s own interfaces.

Start firewall puts your saved policy in force: on Linux it loads the rules, on Windows it switches the firewall profiles on. Stop firewall takes StockFW’s rules out again (Linux) or switches the profiles off (Windows), and the card turns red, because that is what it means. View events jumps to the Events page.

On Linux, Start firewall and the start on program startup preference read the saved policy first and go through the same gate as Apply, so the firewall never briefly runs an empty policy.

The counters

Four tiles count since the app opened: inbound events (with how many were blocked), outbound events, open connections (with how many programs own them), and traffic right now across your adapters. “Idle” means no bytes in the last second. These are the same numbers the Events and Activity pages show in detail.

Open connections

Every established TCP connection, with the program that owns it, the remote address, the port, the service name and the direction. On Linux the program is found through /proc/<pid>/fd; on Windows through the TCP table. When the owner cannot be read the cell shows ?, never a guess.

Direction is decided by what is listening: a connection on a port that something on this computer listens on was accepted, so it is Inbound and named by that port. Only connections nobody listens for fall back to guessing from port numbers, which is what older versions did for everything and got wrong whenever both ends were high ports. [[verified:test-core.sh]]

Connections between two programs on this computer are hidden by default and counted at the bottom of the table (“2 local connections are hidden · Show them”), and so are the dashboard’s own sockets, which exist only because someone is looking.

Network adapters

Each adapter with its type (Ethernet, Wireless, Virtual), address, totals and current rate. Virtual adapters, which is what Docker bridges, VM networks and VPN tunnels create, are hidden by default and counted, with Show them to list them. On Linux the type comes from sysfs: a wireless extension means Wireless, a backing bus device means Ethernet, anything else is Virtual.

Recent blocks

The last few blocked connections, each with the remote address, what blocked it (your policy, or Sentinel) and the time. All events opens the Events page. When nothing has been blocked since the app opened, the card says so instead of showing an empty list.

Lock policy

The button in the top corner. While the policy is locked, every Apply, from any page or from the command line, becomes a dry run: the change is measured and saved, an audit line reads “policy held, firewall untouched”, and the engine is left exactly as it is. Use it when you are editing a policy you do not want to apply piecemeal. Audit-only mode on the Policy page does the same thing from the other side. [[verified:test_apply_gate]]

The sidebar

The sidebar lists the pages: Overview, Events, Activity, Policy, Threat Intel, Copilot and Trust. Its bottom repeats the verdict, Protected or Not protected, with the engine’s name, so it is visible from every page. Preferences, Help and About StockFW sit above it; F1 opens the help at the topic for the page you are on.
