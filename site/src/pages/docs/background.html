Background and the tray

The firewall engine runs whether StockFW is open or not; StockFW in the background is what keeps watching events, learning behaviour and, in auto mode, letting Sentinel act. The tray icon is how you know it is there and how you get it back.

Turning it on

Two settings on the Interface preference page, both on by default: Show a tray icon and Minimize to the tray. With both on, closing or minimising the window hides it and StockFW keeps running. With the icon off, closing the window quits the program; StockFW will not hide a window it cannot give back, because a background process with no way to reopen it would be a zombie with root rights. [[verified:ui-tray-smoke]]

The icon and its tooltip

The tooltip reads StockFW, Protected or StockFW, Not protected, with the engine’s name, from the same state the Overview shows; when the state cannot be read it says Firewall state is unknown rather than guessing. The icon follows the state too, so the answer to “is my firewall running?” is one glance.

The menu

  • Open StockFW brings the window back.
  • About StockFW shows the version and credits.
  • Quit StockFW ends the program. It does not stop the firewall: the engine keeps enforcing whatever was last applied, exactly as it would if StockFW crashed. To stop filtering, open the window and press Stop firewall, or run sudo stockfw stop.
Coming in 1.0.7

A richer tray menu: the state, the last few blocks, Start and Stop, and the Sentinel mode, without opening the window. Quit stays a plain quit.

What runs in the background

  • Event monitoring, and everything fed by it: the Activity counters, the Copilot’s baseline, Sentinel’s detectors.
  • Sentinel’s ten-minute expiry timer for auto-blocks.
  • In 1.0.7, the hourly check for threat-intel feed updates. [[soon]]

Memory stays flat: the Activity series are fixed-size rings, the Events list keeps 2,000 rows, the Copilot keeps 200 insights, and a 150-second soak at full event rate found no growth. [[measured:150-second soak, docs chapter 9]]

Where the icon cannot appear

A tray needs a tray host. GNOME has not shipped one since 3.26; the AppIndicator extension restores it, and KDE, XFCE, MATE, Cinnamon and Windows have one built in. Without a host the icon simply does not show, the window keeps working, and closing it quits, so nothing is lost. The project’s own tray test fails on a headless machine for this reason, and is expected to. [[gap]]

Starting at login

StockFW does not install itself as a login item or a service. On Windows the elevated shortcut needs a UAC prompt, which a silent start cannot give, so an autostart entry would start the unprivileged copy. On Linux a desktop autostart entry under ~/.config/autostart/ runs as you, not as root, with the same limits. If you want the firewall itself in force at boot, see what happens at reboot.
