Troubleshooting

StockFW tries to say what is wrong in the place where it is wrong. This page collects those messages, says what each one means, and what fixes it.

Privileges

“Administrator privileges required”, “Not live yet: run `sudo stockfw apply’”, exit status 3
You are changing the firewall without the rights to do it. The change is saved and will be applied the next time Apply runs with rights. On Windows use the StockFW (Elevated) shortcut; on Linux run sudo /usr/local/bin/StockFW or sudo stockfw apply. Nothing was half-applied.
“sudo: StockFW: command not found”
[[linux]] sudo does not search /usr/local/bin on Debian, Kali and Ubuntu. Type the full path: sudo /usr/local/bin/StockFW. The installer warns about this and deliberately does not edit sudoers; see why.
“Windows protected your PC” when running the installer
The installer is not code-signed yet. Check the SHA-256 against the download page, then More info, Run anyway.

Events

“Monitoring is not available” on Windows
The audit policy that makes Windows write firewall events is off. Open the elevated app once; it enables it. Or run auditpol /set /subcategory:"Filtering Platform Connection" /success:enable /failure:enable in an administrator PowerShell. See Enable monitoring. If a domain policy forces auditing off, StockFW cannot override it and says so.
“Monitoring is not available” on Linux
The kernel log needs root. Start the app with sudo, or add yourself to the adm group for the command line’s events.
The list stays empty although the firewall is running
Read the sentence under the empty list. “Waiting for the first event” means nothing has been blocked or logged yet; try an inbound connection from another machine to a closed port. On Linux, allowed connections are logged only with Log allowed connections on; otherwise the page shows drops and rejects only.
No events in WSL2, a container or a network namespace
[[linux]] The kernel delivers firewall log lines from a non-initial network namespace only when net.netfilter.nf_log_all_netns=1. Set it on the host: sudo sysctl -w net.netfilter.nf_log_all_netns=1. WSL2’s kernel also needs the netfilter log modules; a stock Ubuntu WSL image has them.
The Program column is empty
[[linux]] The kernel log carries no program name. The Overview’s connection table names programs for connections that are open; the Events page cannot for ones that are not. [[gap]]

Policy and Apply

A rule I added is not applied
[[linux]] Check which policy you edited. As yourself the policy is ~/.stockfw; as root it is /etc/stockfw. stockfw status prints the directory in use. Pick one identity for policy work; see Two homes.
“N malformed policy rules were skipped”
A line in a policy file did not parse: a non-numeric port, a host name starting with a hyphen, a stray comma. The line was skipped, not guessed at. Open the file named in the message, fix or delete the line, reload. Saving from the app writes only the rules that parsed. The format.
Apply says “policy held, firewall untouched”
Audit-only on the Policy page or Lock policy on the Overview is on. The change was measured and recorded; the engine was left alone. Turn the hold off and Apply again.
Apply failed and “the last good policy was restored”
The engine refused a rule. The dialog carries the tool’s own message; on Windows it is often a target netsh cannot parse, on Linux a rule the kernel lacks a module for. The policy on the wire is what it was before you pressed Apply. The audit log has the line.
“The forward to 192.168.1.30 was left out: no external interface is set”
Port forwards need router mode: set the Internet connected network device and Enable Internet connection sharing on the Network Settings preference page.
“NOT BLOCKED: name could not be looked up”
A deny rule’s target is a host name that did not resolve while the firewall was being started, so it was left out rather than refuse to start at all. Fix the name or use the address, then Apply again; while the firewall is running, the same failure refuses the apply and keeps the old addresses blocked instead.
A host-name rule covers nothing on Windows
[[win]] Windows Firewall takes addresses only. Use the address, or one rule per address. The Covers column warns.

IPv6

The IPv6 tile reads “Not filtered: ip6tables is not installed”
[[linux]] sudo apt install iptables brings ip6tables on Debian-family systems; dnf install iptables-nft on Fedora. Then Apply again. Until then only IPv4 is filtered, and the app says so rather than pretending. [[gap]]
“None on this system”
The kernel has no IPv6 stack. Nothing to filter, nothing wrong.

Copilot and Sentinel

Sentinel blocked something I use
Select the finding and press Undo auto-block, or right-click the destination on the Events page and Allow destination: your Allow lifts the block and the two reach the firewall together. The block would have expired by itself in ten minutes; it cannot come back in this session. If it happens often, set Sentinel to Detect only, which takes every staged block down at once. Sentinel never blocks loopback, your LAN, multicast or a destination the program has used before; if it did, that is a bug worth reporting with the audit lines.
No insights appear
The baseline needs history: four distinct hours before it judges hours, eight ten-minute windows before it judges rate. Novelty findings go quiet for a program whose profile is marked partial. Run analysis only reports what the policy and the events so far support.

Tray and window

No tray icon
Your desktop has no tray host (GNOME without the AppIndicator extension, or a headless session). The window works as usual and closing it quits. See Background and the tray.
I closed the window and the app is still running
That is Minimize to the tray. Open it from the tray icon, or quit from the tray menu. Quitting does not stop the firewall.

Command line and dashboard

“cannot listen on 127.0.0.1:8080”
The port is taken. Leave out --port and the system picks a free one.
The dashboard did not open a browser
Under sudo StockFW will not start a browser as root. Copy the printed URL into your own browser. The token is in it.
The dashboard page shows “Unauthorized”
The browser tab lost the token: the #token=… fragment was cut from the URL before the page loaded, the tab was reopened in a new session, or the URL is from an earlier run. Start again and open the freshly printed URL.

Uninstalling and starting over

Rules are still in the firewall after uninstalling
By design the uninstaller leaves the engine as it is. Press Stop firewall before uninstalling, or afterwards: on Linux sudo iptables -D INPUT -j INBOUND; sudo iptables -F INBOUND; sudo iptables -X INBOUND and the same for OUTBOUND and the nat chains; on Windows delete the StockFW- rules in wf.msc.
Start from scratch
Stop the firewall, close the app, delete the two directories listed in Files and formats. The next start is a first run.

Reporting a problem

Open an issue on GitHub with the version (About StockFW or stockfw version), the platform, what you did, what the app said, and the relevant lines of audit.log. Nothing in the audit log is secret, but read it before pasting; it names your rules’ targets.
