# StockFW 1.0.8 Implementation Plan (develop/1.0.8 branch)

**Branch:** `develop/1.0.8` (created from `main` @ `001cc01`)
**Audit:** `AUDIT-1.0.8.md` written to repo root.

## P0 — Fix existing defects

### P0-A: Transactional Windows apply (`firewalled_apply_rules`)
- **Defect:** clears all StockFW rules first, then re-adds per-rule via netsh; a mid-apply failure leaves a partial policy (old rules cleared, only some new ones created). Violates principles #2, #3, #4.
- **Fix:** snapshot current StockFW-owned rules before clearing; on failure, roll back to the snapshot; never report success on partial application.
- **Files:** `port/src/platform/windows/fs-backend-windows.c`
- **Test:** new regression test in `port/tests/` (scripted fake backend or real netsh in CI).

### P0-B: Event → per-app rule path
- **Defect:** `fs-winevt.c` `make_hit()` extracts `Application` basename only, drops full path. `FsHit` has no `program` field.
- **Fix:** add `program` to `FsHit`; preserve full path from `Application` XML field.
- **Files:** `port/src/core/fs-types.h`, `port/src/core/fs-winevt.c`

## P1 — Reliability & claims

### P1-A: VPN coexistence test matrix
- WireGuard, Proton, Mullvad, NordVPN; connect before/after StockFW, disconnect, reconnect, interface switch, IPv4/IPv6, DNS, reboot, rollback.
- Document results before making public reliability claims.

### P1-B: Code signing
- Authenticode signing for Windows binaries via CI/GitHub secrets; never commit private keys.
- Verify signatures after signing.

### P1-C: Import/Export UX
- One-step export/import, preview, validation report, duplicate detection, backup before import, rollback on failure.

## P1 — Linux app rules (architecture decision)

- Investigate cgroup v2 / nftables cgroup matching / socket-owner. Likely defer to 1.0.9 with a clear capability boundary.
