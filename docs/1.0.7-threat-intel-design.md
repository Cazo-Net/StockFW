# StockFW 1.0.7 design: IPv6 on Linux, threat-intel blocklists, country/ASN blocking

Status: design for implementation. Chosen by LEPL on 2026-11-02 ("IPv6 + threat-intel blocking").
Context: `docs/ARCHITECTURE-AND-SECURITY.md` Chapter 13.9 (Linux IPv6 gap) and the IPFire gap analysis.

## 0. Goals and non-goals

Goals

1. **IPv6 is filtered on Linux** with the same policy as IPv4, without breaking IPv6 itself
   (neighbour discovery, router advertisements, PMTU, DHCPv6 replies).
2. **IP blocklists ("threat-intel feeds")**: the user opts in to well-known feeds; StockFW downloads,
   validates, normalizes and stores them, and blocks listed addresses inbound and outbound.
3. **Country and network-owner (ASN) blocking** from an offline location database built from a
   public-domain / open source.
4. **Enrichment**: every event and connection can show the remote country, network owner (ASN + name),
   and which blocklists contain the remote address.
5. Every one of these is visible and controllable in the desktop app, the `stockfw` CLI (JSON), and
   (read-only) the local dashboard.

Non-goals for 1.0.7: DNS/domain filtering, IDS, gateway features, a native nftables backend for the
*policy* (that is 1.0.8; 1.0.7 uses nftables only for the threat-intel sets), signed feeds (no feed
offers signatures; see the integrity section for what we do instead).

House rules that apply to all of it: local-first and **no network traffic unless the user enabled a
feed** (StockFW is otherwise offline); WYSIWYG (never claim protection that is not in the kernel);
argv-only process spawning (no shell); every security claim has a test with teeth.

## 1. IPv6 on Linux (iptables backend)

- `fs-script.c` gains a family dimension: `fs_script_generate_inbound_family()` /
  `fs_script_generate_outbound_family()` with `FS_SCRIPT_V4` / `FS_SCRIPT_V6`. The existing
  `fs_script_generate_inbound/outbound()` stay and mean IPv4 (no behaviour change for callers).
  The v6 script uses the token `$IP6T` (mapped to `ip6tables`), the v4 script keeps `$IPT`.
- Rule targets are classified: IPv4 literal/CIDR → v4 only; IPv6 literal/CIDR → v6 only;
  "anyone"/empty → both; hostnames → both (iptables/ip6tables resolve A/AAAA themselves at insert time;
  a name with no AAAA makes ip6tables fail → that one rule is skipped with a warning, not a failed apply).
- v6 ICMP (`-p ipv6-icmp --icmpv6-type ...`), placed in the ICMP section, i.e. **before** the
  `ctstate INVALID` drop:
  - always (whatever the ICMP page says): `packet-too-big`, `time-exceeded`, `parameter-problem`,
    `neighbour-solicitation`, `neighbour-advertisement`, `router-solicitation` (all with `-m hl --hl-eq 255`
    for the NDP ones), `router-advertisement` (`-s fe80::/10 -m hl --hl-eq 255`), MLD
    (130,131,132,143 from `fe80::/10`). Without these the host loses IPv6 connectivity.
  - per Preferences: echo-request/echo-reply (limited like v4), destination-unreachable
    (mapped from `icmp_unreachable`/`icmp_mstraceroute`), traceroute UDP 33434 as v4.
  - v4-only types (timestamp, address-mask, source-quench, redirect) have no v6 rule.
  - "ICMP filtering off" → allow all ICMPv6 (rate-limited like v4).
- DHCPv6 client replies: `-p udp -s fe80::/10 --sport 547 --dport 546 -j ACCEPT` (replies to a
  multicast solicit are not matched by conntrack).
- Reserved sources on the external interface (v6 analogue of the RFC1918 block): `::1/128`,
  `::ffff:0:0/96`, `2001:db8::/32`. ULA and link-local are **not** blocked (both are legitimate on a LAN).
- Broadcast rules: none in v6 (no broadcast). NAT/MASQUERADE: v4 only (documented).
  Port-forward DNAT is emitted in the family of its `to` address only.
- Default action: v6 LOG with the same `STOCKFW-DROP`/`STOCKFW-REJECT` prefix; REJECT uses
  `--reject-with icmp6-addr-unreachable`.
- Backend: `apply_lines()` accepts `iptables` and `ip6tables` argv; apply runs v4 then v6;
  stop/clear detach+flush+delete both families; `get_state` is driven by the v4 chain as before.
- New vtable slot `ipv6_state(&detail)` → `FILTERED` (v6 INBOUND exists and is hooked from INPUT),
  `UNFILTERED` (v4 running, v6 not; detail says why), `ABSENT` (kernel has no IPv6:
  no `/proc/net/if_inet6`), `UNKNOWN` (not root / cannot tell). Windows returns `FILTERED`
  (Windows Firewall rules cover both families). Shown on the Status page, `stockfw status`, dashboard.
- If `ip6tables` is missing or the v6 apply fails while the kernel *has* IPv6, the apply result is
  `FS_APPLY_PARTIAL` with a message naming IPv6; when the kernel has no IPv6 at all it is `FS_APPLY_OK`.
- The kernel log parser names `PROTO=ICMPv6` events "ICMPv6".

## 2. Address ranges (`core/fs-iprange.[ch]`)

One small, heavily tested module does all address arithmetic: parse single addresses, CIDRs and
`a-b` ranges (v4 and v6, strict `inet_pton`), keep **sorted, merged, inclusive intervals**
(v4 as `guint32`, v6 as a 128-bit pair), union, subtract, membership by binary search, and print
(`a`, `a/n` when aligned, else `a-b`). nftables interval sets reject overlapping elements and
Windows rules are smaller when merged, so every consumer gets normalized sets.

**Protected ranges** (never blocked by any list, country or ASN — subtracted, not just skipped):
v4 `0.0.0.0/8, 10/8, 100.64/10, 127/8, 169.254/16, 172.16/12, 192.168/16, 224/4, 240/4`;
v6 `::/128, ::1/128, ::ffff:0:0/96, fe80::/10, fc00::/7, ff00::/8`. TEST-NETs are not protected
(tests use them). Plus the user's **exceptions** list and the system's DNS resolvers
(`/etc/resolv.conf` nameservers, parsed by a pure function), so a feed can never cut DNS, the LAN,
loopback or IPv6 neighbour discovery.

## 3. Feeds (`core/fs-feed.[ch]`)

Catalog (all **off** by default; "Recommended" preset = Spamhaus DROP v4+v6, Feodo, DShield):

| id | source | format | why |
|---|---|---|---|
| spamhaus-drop | https://www.spamhaus.org/drop/drop_v4.json | Spamhaus NDJSON | hijacked/criminal netblocks |
| spamhaus-dropv6 | https://www.spamhaus.org/drop/drop_v6.json | Spamhaus NDJSON | same, IPv6 |
| feodo | https://feodotracker.abuse.ch/downloads/ipblocklist_recommended.txt | plain | botnet C2 (outbound!) |
| dshield | https://feeds.dshield.org/block.txt | DShield | top attacking /24s |
| firehol-level1 | https://iplists.firehol.org/files/firehol_level1.netset | plain | FireHOL aggregate |
| blocklist-de | https://lists.blocklist.de/lists/all.txt | plain | fail2ban reports |
| et-compromised | https://rules.emergingthreats.net/blockrules/compromised-ips.txt | plain | compromised hosts |
| cins-army | https://cinsscore.com/list/ci-badguys.txt | plain | CINS Army |
| tor-exits | https://check.torproject.org/torbulkexitlist | plain | Tor exit relays (policy choice) |

Each entry also carries a `mirror_url` on the FireHOL GitHub mirror
(`https://raw.githubusercontent.com/firehol/blocklist-ipsets/master/<name>.(net|ip)set`) where one exists;
the fetcher tries the primary, then the mirror. Custom feeds: any `https://` URL + format.

Parsing is strict and bounded: max 32 MiB, max 1,000,000 entries; comments `#`/`;`, trailing
`; SBL…` text, CR/LF, BOM; invalid lines counted (not fatal unless nothing parses);
host bits masked (counted); entries broader than **/8 (v4) or /16 (v6)** are rejected as too broad
(a poisoned feed must not be able to block the internet); result normalized and protected ranges
subtracted later at build time.

## 4. Fetch, store, integrity (`core/fs-intel.[ch]`)

- Download by spawning `curl` with an argv (curl ships with every Linux distro and with Windows 10+):
  `--proto =https --proto-redir =https --tlsv1.2 --fail --silent --show-error --location --max-redirs 3
  --max-filesize 33554432 --max-time 120 --user-agent StockFW/<ver> --output <tmp> --url <url>`.
  The URL is validated first (https only, ≤ 2048 chars, no whitespace/controls, no userinfo,
  must not start with `-`). Proxies come from the environment, TLS from the system CA store.
  Tests inject a fake fetcher (`fs_intel_set_fetcher`).
- Store: `$STOCKFW_INTEL_DIR`, else `/var/lib/stockfw/intel` (root on Linux),
  `<rules dir>/intel` otherwise. Per feed: `<id>.list` (normalized ranges, one per line, written
  atomically: temp + rename, 0644) and `<id>.state` (key file: fetched_at, attempted_at, sha256 of the
  raw download, entry counts, parse stats, last_error, source URL used). Config: `intel.conf` (key file).
- Integrity in lieu of signatures: HTTPS only; size/entry caps; strict parse; too-broad rejection;
  protected-range subtraction; **shrink guard** (a list that falls below 25 % of its previous size when
  the previous had ≥ 100 entries is refused and the previous copy kept, unless `--force`);
  a failed or refused update never deletes the previous good copy; staleness is reported
  (older than 7 × interval → "stale").
- Update schedule: each feed has an interval (default 24 h, Spamhaus 12 h). `stockfw intel update`
  updates the due feeds (or one / `--force`); the Linux installer ships a systemd timer
  (`stockfw-intel-update.timer`, daily, **disabled**; `stockfw intel schedule on|off`).
  The desktop app (as root) checks hourly for due feeds while it runs.

## 5. Location database (`core/fs-geo.[ch]`)

- Default source: **iptoasn.com** `ip2asn-combined.tsv.gz` (public domain, PDDL; columns
  `start end asn country description`), giving both country and ASN with the owner's name.
  Also accepted (import from file or URL): CSV `start,end,cc` (country) and `start,end,asn,org` (ASN)
  — the ip-location-db / DB-IP Lite layouts — so an air-gapped user can import files fetched elsewhere.
- Compiled once into a compact binary file `location.sfwgeo` (magic `SFWGEO01`, little-endian,
  header with counts and offsets, sorted v4/v6 country tables, v4/v6 ASN tables, AS-name table,
  string pool). Lookups are binary searches over a `GMappedFile`; **the reader bounds-checks every
  offset and count** (the file is treated as untrusted).
- Country names: built-in ISO 3166-1 alpha-2 table (English). Codes are validated against it.
- Blocking: selected countries and ASNs → their ranges, merged, minus protected/exceptions → one
  `geo` set (inbound by default, optionally both directions).

## 6. Ruleset and enforcement

`FsIntelRuleset` = list of `FsIntelSet { id, label, dir (in/out/both), FsRangeSet *ranges }`:
one per enabled feed (`feed:<id>`), one `geo`. Built from config + store + geo DB, after subtracting
protected ranges, DNS resolvers and exceptions.

**Linux** — one nftables table owned by StockFW, replaced atomically with `nft -f -` (script on stdin):

```
table inet stockfw_intel { }            # create-if-missing so the delete below cannot fail
delete table inet stockfw_intel
table inet stockfw_intel {
  set s_<n>_4 { type ipv4_addr; flags interval; elements = { ... } }
  set s_<n>_6 { type ipv6_addr; flags interval; elements = { ... } }
  chain input   { type filter hook input   priority filter - 10; policy accept;
                  ip saddr @s_<n>_4 limit rate 5/second burst 10 packets log prefix "STOCKFW-TI <id> " level info
                  ip saddr @s_<n>_4 counter drop  ... }
  chain output  { type filter hook output  priority filter - 10; policy accept;  (daddr, for out/both) }
  chain forward { type filter hook forward priority filter - 10; policy accept;  (both) }
}
```

Separate from the iptables policy chains, so a policy apply never touches it; firewall **stop removes
it**, start re-applies it. A transaction either applies whole or not at all, so a failed apply leaves
the previous blocklists in force (reported as such). nft missing → clear error, policy unaffected.
Per-set counters (`nft list table`) feed "blocked N packets" in the UI. Log lines carry
`STOCKFW-TI <set-id>`; the kernel-log parser fills the new `FsHit.rule` ("Threat intel: Spamhaus DROP",
"Location block").

**Windows** — `netsh advfirewall firewall add rule name="StockFW-TI <set> <dir> <k>" dir=in|out action=block
remoteip=<chunk>` with chunks of ≤ 1000 ranges and ≤ 8000 characters; rules created are recorded in
`netsh-rules.txt` in the intel dir and deleted by exact name before a re-apply/clear (block rules
win over allow rules on Windows, which is why exceptions are subtracted in core, not expressed as
allow rules). The argv generation is a pure core function tested on Linux; the thin glue in the
Windows backend is marked [Unverified on Windows] until run there.

**Gate** — `fs_intel_apply_safe(backend, ruleset, source, hold)` honours audit-only mode and the
Policy Lock exactly like the policy gate (`FS_APPLY_DRY_RUN`, firewall untouched) and writes one
audit line per attempt.

## 7. Enrichment and surfaces

- `FsIntelLookup`: country (code + name), ASN + owner, the feeds that list the address, and whether
  it is protected/exempt. Backed by the loaded lists and the geo DB; a v4-mapped v6 address is looked
  up as v4.
- Desktop: new **Threat Intel** page (master switch, feed table with toggle/entries/age/status/blocked
  counter, Update now, custom feed, country picker with search, ASN list, direction, exceptions,
  lookup box, location-data source/age/attribution, IPv6 state); Events and Connections gain
  **Country** and **Network** columns (+ "Lists" in the tooltip); Status page shows IPv6 state and
  threat-intel summary. Changes go through the gate.
- CLI: `stockfw intel status|feeds|enable|disable|update|apply|clear|lookup|countries|block-country|
  unblock-country|block-asn|unblock-asn|except|unexcept|geo-update|geo-import|schedule` with `--json`;
  `status` gains `ipv6` and `intel` objects; `events`/`connections` JSON gain `country`, `asn`,
  `as_name`, `lists`.
- Dashboard (still read-only): IPv6 + threat-intel tiles; Country/Network columns.

## 8. Test plan (teeth)

- iprange: parse matrix, merge/adjacency, subtract splits, protected subtraction, v4-mapped lookup,
  printing round-trip; each with a re-injected bug proving the check fails.
- feed parsers: each format, hostile input (huge lines, NULs, 0.0.0.0/0, ::/0, /7, BOM, CRLF,
  1M+1 entries), shrink guard, fake fetcher (no network).
- geo: build from fixtures, lookup, corrupted/truncated file fuzz (no crash, clean error).
- nft script: golden checks + **`nft -c -f`** validation and a real apply/list/delete in a network
  namespace (`unshare -n`), plus a packet test over a veth pair proving a listed address is dropped and
  an exception is not.
- ip6tables: generated v6 script checks; real apply in a namespace; NDP/PMTU rules present before the
  INVALID drop; foreign v6 rules survive; stop removes both families.
- CLI and UI smokes extended; adversarial suite gains intel cases.
